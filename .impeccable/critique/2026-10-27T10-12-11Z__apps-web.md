## 反模式判定（AI 味测试）

**总体判定：未命中 2026 年主流 AI slop 特征，营销页是近期同类输出中的上乘之作。**

- 无渐变文字、无玻璃拟态、无奶油底色、无侧条纹边框、无相同卡片网格堆砌（TeamRoster 4 卡有角色差异化文案与技能 chips）
- HowItWorks 的 01/02/03 编号是真实三步流程（描述→调度→交付），编号承载语义，合规
- 自定义 SVG 场景（圆桌 CEO 派发）标注「示意插画」——诚实，且非手绘涂鸦风
- **残留 AI 味**：hero H1 `lg:text-[56px] tracking-tighter`（-0.05em，低于 -0.04em 下限，大标题字距局促）；eyebrow 小标签只出现在部分 section（HowItWorks/TeamRoster 有，ValueStrip/CaseSection 无），节奏不统一；CaseSection 是全站唯一 `font-bold` 标题

**确定性扫描（detect.mjs）**：4 项警告 ——
- 3× `gray-on-color`（quality-rules:285 / sop-workflows:384 / technical-rules:323）：核实为**条件类误读**（启用态实际渲染 `#00875a on green-50` = 4.55:1 达标），但同行的「停用」徽章 `gray-500 on gray-100` ≈ 4.4:1 确在临界线下，值得顺手修
- 1× em-dash（layout.tsx）：命中 metadata 标题/描述，中文破折号属规范用法，**软性发现/基本误报**（另 2 处为代码注释）
- 检测器未发现渐变文字/侧条纹等硬性禁令命中 —— 与人工审查结论一致：硬性反模式干净，问题集中在系统性一致性与对比度

**对比度实测（token 计算）**：token 体系全部达标（正文 16.26:1、次要文本 8.89:1、主按钮白字 4.70:1、营销暗色面 13.04–19.61:1）。**越界全部来自绕过 token 的写法**：`text-gray-400` 空态/辅助文字 **2.54:1**（48 处）、硬编码橙 `#e8740b` 小字号表格文字 **3.03:1**（9 处）。

## 总体印象

营销页已经讲了新 spec 的故事，工作台还活在上一章。骨相是好的——token 体系健康、流式体验用心、溯源意识贯穿——但三张面孔（暗色营销/亮色工作台/灰阶 admin）像三个产品缝合，且从「立即派发任务」到「创建工作区」的词汇断层每天都在提醒访客：承诺和交付之间隔着一个尚未开工的 Phase 1。**最大的单一机会：在 Phase 1 动工前先收敛设计系统与状态词汇表，让四类新页面（§3.3）长在同一套地基上。**

## 做得好的

1. **营销页 hero 是真功能不是装饰**——textarea 带 1000 字计数器、「派发给 AI 团队」真实 POST `/api/v1/projects/wizard` 并路由进工作台，比行业常见的假输入框高一个档次。
2. **流式对话的状态设计**——常驻可折叠「深度思考中」面板（3 脉冲点 + 打字机光标）、自动收起为「已深度思考」、附件托盘的 9 态解析徽章（待解析→已归类/待确认），把异步过程的心智负担做没了。
3. **诚实的空态策略**——CaseSection 800ms 超时后回落到 3 个设计好的占位案例（代码注释明言「永不让落地页出现 spinner 或暂无案例空洞」）；示意插画明确标注。这与 AGENTS.md「缺失信息须明示」的产品原则同构。

## 优先问题

### [P1] 营销承诺与工作台交付的词汇断层
- **是什么**：hero 卖「组建你的 AI 团队 / AI 大脑（CEO）统筹交付」，CTA「立即派发任务」落地后是「项目列表 / 工作区名称 / 所属行业 / 知识问答」——团队、员工、任务、派发在登录后全部消失。
- **为什么重要**：这是 spec Phase 1 缺口在当下 UX 的直接显形。每个从营销页进来的新用户都要自行完成「任务≈项目、AI 员工≈知识问答」的错误映射，首访流失点。
- **怎么修**：Phase 1 落地前，最小改动是让 hero 落地页与后续页面共享同一套名词（过渡期可将「项目」明确定位为「任务的工作区」并在向导文案中衔接）；Phase 1 动工时按 spec §3.3 直接以团队/任务 IA 重建工作台首层。
- **建议命令**：`$impeccable shape 团队工作台与任务视图（spec §3.3）`

### [P1] 设计系统碎片化——admin 绕过 token 体系
- **是什么**：19 个文件混用原生灰阶（62× `text-gray-500`、48× `text-gray-400`、24× `border-gray-200`）与硬编码 hex（15× `#00875a`、9× `#e8740b`、还有 `#00D4FF` 青色「评审中」状态）；4 套状态徽章体系并存（status-tag.tsx / PARSE_STATUS_META / 各页本地 statusColor / board token）；8+ 处 `bg-primary hover:bg-primary` 悬停失效按钮；`error.tsx` 用了体系外的藏青 `#1A2B3C`。
- **为什么重要**：spec §3.3 的四类新页面需要「在线/忙碌/fired、预算水位 80/100 两级预警、HITL 等待」等一整套新状态词汇——在四套并存的现状上叠加只会变成五套。且其中 `gray-400`（2.54:1）与 `#e8740b`（3.03:1）实测不达标，空态文字与表格小字直接不可读。
- **怎么修**：统一收敛到 M3 token（`--color-success/-warning` 已存在却未被使用）；建立单一 StatusBadge 组件吞并四套实现；`$impeccable extract` 把 token 清单固化为 DESIGN.md。
- **建议命令**：`$impeccable colorize admin 状态与文本色收敛到 token`，随后 `$impeccable document`

### [P1] 移动端导航死区
- **是什么**：TopNav `hidden md:flex`，`<md` 下导航链接全部消失且无汉堡菜单；移动端用户无法回到项目列表（仅剩 logo 点击回首页）。
- **为什么重要**：内部销售在手机上查看项目进展是真实场景；当前移动端是被截肢的。
- **怎么修**：补一个 `md:hidden` 的抽屉式菜单（radix Dialog/Drawer 已在依赖里）。
- **建议命令**：`$impeccable adapt top-nav 移动端`

### [P2] 表单校验与错误 UX 不对称
- **是什么**：登录/hero 有手写内联校验，向导必填项（`工作区名称 *`）无任何强制、无字段级错误；zod 是依赖却全站未用于 UI；登录错误只有顶部 banner 一条。
- **怎么修**：统一 zod schema + 字段级错误展示；向导步骤末校验必填。
- **建议命令**：`$impeccable harden 表单校验`

### [P2] 高频用户的效率真空
- **是什么**：无快捷键、无命令面板、admin 表格无批量操作（逐条删除）、17 项平铺侧栏无分组无搜索。
- **为什么重要**：知识运营是高频角色（PROJECT_SPEC「使用频率：高」），spec 的 @fast-path 与 HITL 审批都会加重键盘流依赖。
- **建议命令**：`$impeccable clarify` + Phase 1 时直接引入 cmd+k 生态

## 对照 spec 的就绪度评估（§3.3 四类页面）

| spec 页面 | 现状 | 就绪度判断 |
|-----------|------|-----------|
| 团队工作台（roster/hire 向导/员工编辑器/fire 确认） | 不存在；最近的是 projects 列页卡片模式 | 卡片网格可复用；但 hire/fire/忙碌态需要新的状态词汇系统（见 P1-2） |
| 团队对话视图（roster 侧栏 + @补全 + direct 流式回复） | ConversationPanel 单专家气泡流 | 内容块渲染器（skill_executing/plan_progress/artifact…）是优良底座；信箱时间线（from/to/seq、@高亮）是新的布局模式，需扩展而非重写；SSE 五种新 chunk 类型（agent_message/task_status/hitl_request/roster_change/budget_warning）前端尚无对应渲染分支 |
| 任务视图（信箱时间线/runs 状态条/预算水位/HITL 审批卡/产物预览） | 不存在 | Artifact 组件可按 spec「复用现有组件」直接引用；HITL 审批卡在营销页 DecisionScene 已有概念预演（tertiary-container 着色的「人工确认门控」）——很好的设计连续性 |
| 组织管理（成员/配额/审计/账单） | 不存在；admin 有 17 项运营导航可挂载 | admin 侧栏需按 spec §1.6 三分（平台运营/租户资产/知识资产）重新分组，17 项平铺不可持续 |

**结构性风险提前指出**：spec 的 SSE `budget_warning`（80/100 两级）与 HITL `waiting_human` 状态要求工作台有全局的「任务进行中」感知位（如顶栏水位/待审徽章），当前 TopNav 无任何通知/状态承载位——Phase 1 设计时需预留。

## Persona 红旗

**Alex（策划·高频专家用户）**：无任何键盘快捷键；admin 案例库删除只能逐条点；17 项平铺侧栏找不到「检索实验室」得靠记忆；eye/edit 两个不同图标打开同一个编辑框，肌肉记忆被背叛。

**Jordan（销售·首次使用）**：被 hero「立即派发任务」吸引 → 落地「创建项目向导」要求填「工作区名称/主题标签/所属行业」——他要的「把任务交给 AI」变成了行政填表；工作区内遇到「SOP/检索/入库」等运营词汇无任何解释 tooltip；项目列表空态只有一行灰字「没有找到匹配的项目」，没有新建引导。

**Sam（无障碍依赖用户）**：`text-gray-400`（2.54:1）的空态与辅助文字不可读；表格操作列纯图标按钮依赖悬停 tooltip（触屏/读屏不可达）；移动端导航整体消失；好消息：核心表单可键盘走完、shadcn 焦点环保留、营销动效全部有 `motion-reduce` 降级。

**小芸（知识运营·项目专属 persona）**：上传 20 份资料只能逐份看解析状态徽章，失败重试藏在每份的 dropdown 里；「停用」徽章灰上灰（≈4.4:1）扫视时认不出；SKU 门控的 9 项导航在她的小版本里消失，但没有说明为什么——她会以为是权限故障。

## 次要观察

- 品牌 string 不一致：metadata「AI 团队平台」vs 导航品牌「AI 团队」vs footer 两者混用
- 向导完成态用 `#10B981` 翡翠绿——全站唯一一处，体系外
- `viewport.themeColor` 是暗色 `#010102`，但工作台/admin 是亮色面
- 冻结画布约 2500 行孤儿组件（canvas-viewport/module-node/version-panel 等）仍在源码树；不影响 bundle（未引用）但拖累维护
- ReactMarkdown prose 覆盖串在 conversation-panel.tsx 两处复制粘贴（262/370 行）
- 登录页 mock 验证码明文展示（「本次验证码：123456」）——开发期方便，生产需门控
- 营销页 hero「AI 大脑 · CEO 自动派发」静态预览无「示意」标注（DecisionScene 有标注，hero 没有）
- 无 `not-found.tsx`；`loading.tsx` 缺失（仅 Suspense fallback）

## 值得思考的问题

- 「项目」这个容器在团队平台里还有必要让用户感知吗——还是应该降级为任务的一个属性，让「任务」成为唯一的首层名词？
- HITL 审批卡出现在对话流里时，用户正处的认知模式是「看 AI 干活」——审批卡需要多强的中断感（modal 级）才能不被划过去忽略？
- 预算水位条是给 owner 的控制感还是给 member 的焦虑感？两种角色的呈现是否应该不同？
- admin 17 项导航若按 spec 三分重组，知识运营的一天会不会从「找功能」变成「走流程」——有没有机会做成任务式而非功能式后台？

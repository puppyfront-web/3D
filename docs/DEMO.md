# 售前方案工作台 — 演示脚本

> 适用：私有化部署 POC / 客户现场演示  
> 预计时长：**15–20 分钟**  
> 规格依据：[PRESALE_DELIVERY_SPEC.md](./PRESALE_DELIVERY_SPEC.md) §14.1

## 演示前准备

| 项 | 说明 |
|----|------|
| 访问地址 | 前端 `http://<主机>:3000`（或生产域名） |
| 登录账号 | `admin@3dwall.com` / `admin123`（演示后请改密） |
| AI 模式 | 开发/POC 可用 `LLM_PROVIDER=mock`；正式演示建议接真实 LLM |
| 案例库 | 首次启动 API 后自动写入 3 条演示案例（标签 `presale_demo_seed`） |

## 演示话术（标准剧本）

**剧本名称：华为裸眼 3D 发布方案**（行业可替换，流程不变）

| 步 | 操作 | 预期结果 | 讲解要点 |
|----|------|----------|----------|
| 1 | `/workspace/projects/new` 创建项目：客户「华为」，行业「科技」，需求「总部裸眼3D幕墙品牌发布」 | 进入 Canvas 工作台 | 「结构化录入，不是一句话丢给 ChatGPT」 |
| 2 | 对话输入：「给华为做一个裸眼3D幕墙的方案，面向科技品牌发布」 | 触发 auto-fill，出现 proposal / 填充卡片 | 「首轮自动调研 + 画布填充 + 策划案初稿」 |
| 3 | 检查画布 | 企业介绍 / 产品技术 / 未来责任有内容 | 「产物落在 Canvas，不是只在聊天里」 |
| 4 | 追问：「刚才填充的企业主营业务是什么？」 | 基于已填充内容回答 | 「多轮不失忆」 |
| 5 | 选中「品牌定位」节点，输入「帮我补充品牌定位」 | 直出成品 + 「采纳到节点」 | 「节点级直出，不是给建议」 |
| 6 | 点击采纳 | 节点更新，可查看来源 | 「人机协作，可追溯」 |
| 7 | 打开策划案 Brief，编辑「创意主题」 | 保存成功 | 「章节可编辑」 |
| 8 | 将全部章节标记 **approved** | 项目状态 → 待审核 | 「审核门控，不是生成即交付」 |
| 9 | 导出 PDF 或 Word | 成功下载，内容非空 | 「对外可交付文档」 |
| 10 | 检查引用 / 待确认项 | 有案例引用或明确待确认 | 「不编造，缺料会标出」 |

## Mock 模式说明

`LLM_PROVIDER=mock` 时：

- 主链路（创建 → 对话 → 填充 → 审核 → 导出）可完整走通
- 文案内容为 Mock 模板，**不代表真实生成质量**
- 向客户说明：「流程与门控是产品能力；接真实模型后文案质量由模型与知识库决定」

## 真实 LLM 演示（推荐签单前）

在 `.env` 或 `docker-compose` 中配置：

```bash
LLM_PROVIDER=openai
LLM_API_KEY=sk-...
LLM_BASE_URL=https://your-provider/v1   # 可选
LLM_MODEL=gpt-4o
```

重启 API 后重复步骤 2–10，目检文案与案例引用。

## 常见问题

| 现象 | 处理 |
|------|------|
| 接口 401 | 先登录 `/login` |
| 跨域失败 | 确认 API `CORS_ORIGINS` 含前端 Origin（含端口） |
| 导出被阻断 | 检查章节是否全部 approved、画布 planning 是否已填 |
| 无案例引用 | 确认 API 已重启并完成 demo seed；后台 `/admin/cases` 可见 3 条演示案例 |
